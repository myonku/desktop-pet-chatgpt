# P2 与 P3 之间 · 素材工具与发布准备

基线为 P2 结项的 `main`，提交 `ebb52f2`。本阶段在 `main` 实施，收口后从 `main` 建立 P3 分支。[P2 结项记录](../../archive/p2/README.md)

## 本轮实施与验收

| 节点 | 实施 | 验收 |
| --- | --- | --- |
| P2 结项 | 归档实施记录和本地证据，迁移剩余实测 | 索引与交叉引用可达，手动运行和严格断网证据各自可查 |
| 根目录 uv | 锁定 Python 环境。现有单体命令保留在 `scripts/`，可导入模块放在 `tools/` | 锁定环境能运行现有合成包生成和发布工具，普通 Cargo 检查可独立运行 |
| 素材优化初版 | 提供 RGBA PNG 帧序列的 alpha 去噪、可选 RGB 去噪和显式 Vulkan 超分入口。输出到独立目录并记录输入、参数和哈希 | 用合成帧检查清理、保护区、RGB 与 alpha 保真、输出顺序和失败时的输出隔离。GPU 路径可用合成图做接口验证，模型效果留给素材实验 |
| 版本与来源 | 装配时可指定本地或正式包版本，约定正式附件与源码同版，并记录上游来源和处理链 | 校验器可读新版本的合成包，发布约定能追溯指定附件与候选输入 |

2026-11-13 在本机 Windows、Python 3.13.15 和 uv 0.12.18 验证工具初版。合成帧通过 alpha 清理、保护区、RGB 滤波、顺序、输入哈希、拒绝覆盖和失败清理检查。Real-ESRGAN 在 RTX 500 Ada 上完成合成图 2× 超分，alpha 与单独缩放结果一致，无效设备编号返回失败且没有发布输出。P1 的 PNG/RGBA/BC7 合成包、P2 两套合成包和带自定义版本的合成 WebM 转换包均通过分发校验，ZIP 内清单保持原样。Cargo 格式检查及默认、全 feature 离线测试通过，两组各 28 项。

## 后续素材实验

批量加工前先定交付动作表，按每个源动作记录目标 ID、用法、帧数、尺寸及纳入状态。原型基线如下。

| 用法 | 本地包状态 |
| --- | --- |
| 启动待机 | `idle` 已入包 |
| 自动行为及预览 | `interact`、`drag`、`land`、`move-left/right` 已入包 |
| 吸边姿态 | `edge-left/right`、`peek-left/right` 待派生，当前使用待机回退 |
| 其他原版动作 | 逐项决定预览、行为绑定或延期 |
| 角色资源 | 默认本地包暂未声明角色图、名称和互动音效 |

按拟交付动作的帧数和每页帧数试算紧凑清单，再装配代表动作估算整包。记录清单相对 1 MiB 上限的余量、各档单页峰值、解包体积和 ZIP 体积。原型的 80 MiB 预算保留作对照，正式候选预算按 G-06 确定。

1. 从上游 v0.5.1 选取 `idle`、一段有特效的互动和一段 30 fps 移动。记录上游清单及输入哈希。固定目标 480×480，比对纯缩放、仅 alpha 清理、轻度 RGB 去噪和 GPU 超分后缩回的结果。检查明暗背景、发丝与翅尖、粒子、逐帧闪烁和循环接缝，记录耗时、GPU、显存及参数。
2. 从选定的待机候选按稳定的参考边界派生 `edge-left/right` 与 `peek-left/right`。校准左右露出比例，验证贴边、点击切换、双击停留、菜单展开和透明区域命中。需要复刻原版的连续展开时，再比较短过渡素材与实时变换的成本。
3. 装配到新的本地候选包。动作按源清单核对 ID、帧数、时序、对齐和移动时窗，派生项记录父动作和参数。运行 `validate-pack --distribution`，检查清单、页和播放预算，比较包体与运行开销，再由维护者选定正式候选。补齐其他原版动作时同时明确预览与行为绑定的范围。

本轮以合成输入验收工具。真实素材处理和派生姿态制作由后续实验执行，候选图像、工作缓存和包体留在本地。GPU 实验结果和正式素材选型可并行于 P3。

## 工程审查复验

2026-11-13 在本地工作树完成以下复验。输出位于 `artifacts/validation/p2-p3/runs/`。

| 项目 | 结果 |
| --- | --- |
| Windows 设置与单屏行为 | `review-settings-20261113-161548/result.json` 记录角色和托盘菜单关闭设置、撤销预览，以及保存与重启。单屏核心回归见 `review-core-20261113-161753/result.json` |
| Rust | 默认和全 feature 各 31 项通过，fmt、Clippy 和默认 Release 构建通过。224×224 合成轮廓的 25,088 个矩形批量创建约 10 ms，逐像素命中正确 |
| 素材优化 | 按 [G-06](../../G-06-validation.md#2-分层验证) 的命令复跑 CPU 和 Vulkan，验证保护区、RGB 滤波、顺序、哈希、2× 输出和错误设备的清理 |
| 480×480 六动作装配 | 使用上游本地清单，`--size 480 --batch 4 --png-only`，共 817 帧和 205 页。紧凑清单 93,500 B，最大 PNG 页约 1.56 MiB，PNG 合计约 266.70 MiB，ZIP 约 266.64 MiB。分发校验和来源记录核对通过，数据见 `review-pack-20261113-161651/result.json` |

按 35 个带播放文件的上游条目估算约 4,316 帧，沿用六动作的紧凑清单比例约需 494 kB。全量清单仍需随最终动作和格式选择复算。480×480 的六动作包已超过 80 MiB 原型预算，最终尺寸、格式和交付动作仍需按画质与包体测量决定。
