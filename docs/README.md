## 当前进度与下一步

- 已收纳 v0.5.1 工程并建立最小 Cargo 骨架。旧工程的本地收纳目录为 `.legacy-v0.5.1/`，由 Git 忽略。历史源码仍可从原提交 `852f4f4` 查阅。
- 下一步锁定原型所需的依赖组合，并用自有透明样本验证窗口合成和基本交互。媒体格式随后通过对照实验确定。
- Cargo 使用默认的工具链发现、配置和环境变量规则。依赖接入时通过 `Cargo.toml` 和 `Cargo.lock` 管理。

## 素材管理方向

根目录 `assets/` 留作本地素材工作目录，由 Git 忽略。授权范围明确后，可评估仅追踪带版本和校验值的压缩素材包。需要比较 Git 中的压缩包、单独分发和本地解包三者的成本，尤其关注大型二进制重复提交造成的历史增长。

程序也可以在逻辑上从压缩包读取资源，但应先验证分帧索引、随机读取和预取延迟。整包解压适合作为简单基线，运行时直读有待媒体实验。现阶段保留两种选择。
