# 发布素材解析与后续归档边界

本次仅分析 `release/BailongPet`，未移动素材。视频逐段完整解码，输出仅在内存中计数，没有生成帧缓存。

## 1. 哪些文件需要保留

| 文件/目录 | 当前作用 | 后续引入源码时的分类建议 |
| --- | --- | --- |
| `outputs/白龙桌宠素材/素材清单.json` | 全部动作入口、台词、时长、校准和移动参数 | 必须保留并版本化；可改目录前先解决路径配置 |
| `outputs/白龙桌宠素材/透明WebM/*.webm` | 35 段唯一的播放素材 | 保持当前功能完整时全部保留；文件合计 153,885,547 字节 |
| `app/sounds/click.wav` | 点击/任务完成提示音 | 源码已有相同文件，不需重复引入；静音时可不使用 |
| `app/sounds/来源.txt`、`Kenney-License.txt` | 音效来源及许可说明 | 保留并核对两者对应关系，前者声称程序合成，后者是 Kenney 音效 CC0 说明，不能直接认定该 WAV 来自 Kenney |
| `tools/ffmpeg.exe` | 当前 WebM alpha 解码的必需外部工具 | 属于平台工具依赖，不是美术素材；单独管理版本、来源、平台和哈希，不宜混入角色资源 |
| `licenses/`、ASSETS.md | 运行库、美术素材许可及来源证据 | 后续重打包需要维护，不是播放资源；不能丢失来源记录 |
| `_internal/`、BailongPet.exe | 打包后的 Python/Qt/native 运行环境 | 不导入源码素材目录，由构建生成 |
| `app/运行状态.json`、`app/显示诊断.json` | 已有运行记录 | 不属于素材，也不能当成发布静态资源提交 |
| `.cmd`、安装 HTML/TXT、README、版本及构建说明 | 启动便利入口、说明、发布元数据 | 归入发布构建模板或文档，和角色素材分离 |

“必需”有两个层次：能显示一个基础桌宠，至少需要有效的基础 idle 和清单，以及当前实现依赖的 Python/Qt/FFmpeg；要忠实保留当前全部功能，则需完整 35 段及其清单、音效。现有实现不是通用的可随意删减素材包，部分键直接索引，不能未经改代码就把其余动画删除。

未发现原始创作工程、分层图、原始无损序列、额外 WebP 或过渡动画文件。这些是处理完成的播放资产，不能推断可以从它们恢复原始制作流程。左右动作各自拥有视频，不应未经视觉和时序验证就用镜像替换。

## 2. 清单结构与实际使用

- 1 段 idle + 5 段 additionalIdleAnimations = 6 段待机。
- variants 为 15 段互动；编号不连续是现状，不表示包内缺文件。
- dragAnimation、landingAnimation、quotaAnimation 各 1 段。
- workAnimations 为 6 个槽位，5 个对象加一个 null；null 是预留槽，不是缺失第六段。
- movementAnimations 为 6 段，包括左右行走、跑步、飞行。
- 全部 file 和 playbackFile 值相同且以 `.webm` 结尾，引用的 35 个路径均存在且唯一；无未引用视频、无 returnTransition。
- 根 version=1 是素材清单格式值，和程序 v0.5.1 不同。
- id 同时用于动作选择和 gzip 缓存文件命名；重命名会改变行为，尤其 idle03—06、work01、庆祝动作 18，以及移动条件。
- durationMs 控制播放持续时间；实际帧率来自视频，清单没有显式 fps。前 33 段为 24fps，两个 move03 飞行为 30fps。当前播放器按 durationMs 均匀映射帧索引，后续重构需保留播放时长。
- renderScale、renderOffset、renderAnchor 是对齐元数据；当前绘制采用底部居中实现。移动另有 moveStartMs/moveStopMs/sourceFacing、部分动作的 movementAngleRange/movementSpeed，不能只复制文件名和时长。
- line、name、bubble 是展示文案或说明，loop 字段存在于部分待机；运行时循环/回退主要由 Pet 的动作状态分支控制，不能假定它是独立通用播放器的全部行为配置。
- 兼容分支在没有 playbackFile 时会把 file 的 `.webm` 替成 `.webp`；未来清单迁移不能仅删除 playbackFile，否则会触发错误后备路径。

## 4. 后续素材进入源码的建议（未实施）

建议使用独立资源根，例如 `assets/characters/bailong/manifest.json`、`animations/`、`assets/sounds/`，FFmpeg 放在单独工具管理流程中。以上是未来设计候选，当前代码仍硬编码 outputs/白龙桌宠素材，直接搬目录会导致无法运行。

导入前先确认美术素材再分发权限，保留现有 ASSETS.md。若可版本化，选择 Git LFS 或带哈希的独立资源版本；不应直接提交整个 release。当前 35 段约 147 MiB，后续替换视频会持续放大普通 Git 历史；Git LFS 还需要单独确认 fork 托管及下载方式。用户希望源码可获得素材，具体存储机制尚未决定。

迁移验收至少包括：35 段引用闭合、文件 SHA-256 基线、24/30fps 及帧数、alpha、动作对齐、拖拽落地、左右移动及移动时窗、任务开场和庆祝、源码/打包资源定位、音效，以及资源缺失时的明确错误。缓存应为生成物，不能把 rgba.gz 当成新的素材源文件；当前缓存以文件大小/mtime 判定有效，跨目录复制与替换时应重新设计内容身份规则。

发布目录完整文件哈希见 [release-inventory.json](release-inventory.json)。运行状态文件可能随用户再次运行而变化；清单用于调查快照，不代表所有文件都适合纳入仓库。
