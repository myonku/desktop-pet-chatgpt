本文维护验收标准。实际结果随阶段记录保存，主线关口见 [G-04](G-04-delivery-plan.md)。失败场景与正常场景同为交付条件。

## 2. 分层验证

纯逻辑：可控单调时钟、固定随机种子，验证移动、动作优先级、隐藏恢复、通知去重和配置迁移。契约：合成 FrameSource/IntegrationProvider 故意发送迟到、乱序、重复、损坏和缺能力事件，验证 generation、request/turn 绑定与背压。

页源契约测试让两个实例产生相同页索引与局部代次，确认旧实例的结果不会清除新请求或替换当前帧。包替换的用户路径按 F-18 重启复验。

P2-03 使用[迁移验收脚本](../scripts/validation/p2/check-migration.py)在独立产品目录下测试发布构建命令。历史样本由旧版写入器生成。验证重复导入、错误输入备份、发布构建重读、运行实例隔离、未完成状态和回滚。Rust 测试覆盖注册表读取、发布前后中断重试和目标冲突。

媒体：自有渐变/透明边缘、长动作、移动样本；无效 manifest、超预算单页、损坏校验和、读取失败、取消与设备不支持。黑/白/棋盘/彩底对照 RGB 和 alpha；PNG 先对参考解码，再比较 BC7，平均误差不能替代边缘观察。

Windows 单屏实机覆盖透明、置顶不抢焦点、输入穿透、托盘恢复、中文输入法、剪贴板、文本选区、长文本滚动、当前屏全屏、锁屏、休眠、GPU/surface 恢复。两套笔记本可分别复测。单屏的 100%/125%/150%/200% DPI 可通过逐次切换系统显示缩放分别验收，混合 DPI 列入多显示器专项。

单屏首次尺寸记录面板可视宽高、EDID 读数、显示模式、缩放、初始 DIP/像素和工作区。通过普通尺寸路径与强制跳过 EDID 的诊断路径分别复测。用逻辑和契约测试覆盖不同物理尺寸、负坐标、坏 EDID 和工作区边界。

在 P2 记录同屏拖动与自主移动交接、跨页播放中的输入响应，以及打开产品设置后的资源开销。现有 P1b 参考机上的页面准备和拖动短测作为对照。事件线程同步等待 GPU 的每次 250 ms 是原型保护上限，F-17 仍按输入到可见反馈的延迟验收。

CI：Windows locked build、fmt、clippy、现有纯逻辑/契约测试；自有 fixtures。GUI 截图/实机证据另存节点记录。开发时序覆写的实验单独标记，按素材原时序完成正式验收。

P2-01 的 [Windows 行为脚本](../scripts/validation/p2/check-windows.py) 只操作主屏上的测试窗口，记录动作、可见性、命中区域和启动尺寸。单屏入口可在任一笔记本运行，即使连接外屏也只验收主屏。

P2-02 用 [设置验收脚本](../scripts/validation/p2/check-settings.py) 分别运行产品配置和开发配置构建。产品用隔离用户目录验证保存、恢复和重启。开发用隔离工作目录验证有无开发 TOML 时均与产品配置隔离。其余覆盖包括单实例、托盘、坏配置、文件占用、素材回退及资源换包。核心验收脚本验证两处都没有可用素材包时拒绝启动。自启注册表读写使用隔离的 HKCU 子键验证。

P2-04 用[离线验收脚本](../scripts/validation/p2/check-offline.py)在只读安装目录及独立用户目录下运行默认发布构建，验证本地资源、窗口行为与偏好重启。断网验收使用无外部客户端的 Windows 测试环境并启用 `--require-disconnected`。记录连接状态、可运行检查点、动作覆盖和代表包开销。正式资源范围和性能矩阵随 P4 验收。

### 多显示器专项

扩展桌面至少启用两块屏幕。混合 DPI 用不同的系统缩放，例如内屏 125%、外屏 100%。单屏环境可执行基础回归，专项独立留档。脚本在一块屏幕时写入 `skipped` 报告并退出。两屏 DPI 相同时记录跨屏结果和混合 DPI 未覆盖。

| 用例 | 验收方式 |
| --- | --- |
| 每屏独立启动与 EDID | 自动在主屏和第二屏分别启动，记录设备名、EDID、DPI、DIP 与像素边长。同分辨率异尺寸的比较使用符合条件的硬件 |
| 拖拽换屏与混合 DPI | 自动将桌宠拖到第二屏，检查保留逻辑边长、落点和新屏工作区约束 |
| 异屏及同屏全屏 | 自动验证原屏全屏时桌宠仍可见，当前屏全屏时隐藏并恢复 |
| 负坐标、显示器拔除 | 实机补测。将外屏排到主屏左侧或上方复跑跨屏用例。角色放在外屏后拔除，确认回到可用屏工作区、旧吸边失效 |

在仓库根运行，两个报告目录各自使用新名称。

```powershell
cargo build --release --locked --features development,window-diagnostics --target-dir target/window-diagnostics
python scripts/validation/p2/generate-fixtures.py
$exe = 'target/window-diagnostics/release/desktop-pet-chatgpt.exe'
$fixtures = 'artifacts/validation/p2/fixtures'
python scripts/validation/p2/check-windows.py --exe $exe --fixtures $fixtures --output artifacts/validation/p2/runs/single-display-01
python scripts/validation/p2/check-multi-display.py --exe $exe --fixtures $fixtures --output artifacts/validation/p2/runs/multi-display-01
```

## 3. 性能实验与预算

| 项目 | 初始目标/口径 | 冻结节点 |
| --- | --- | --- |
| 首次可交互 | 进程启动至首帧且拖拽/菜单可用 ≤2s，不以占位单帧替代交互 | P0 口径，P1a/P1b 测量 |
| 输入响应 | 输入事件至可见反馈 p95 ≤100ms；另报 p50/p99 | P0 |
| 播放丢帧 | 24/30fps 原时间序列；稳定播放 <1%，报告缺失应呈现帧/应呈现帧数 | P0 |
| CPU 素材缓冲 | P1b 本地原型 ≤32 MiB，包含读取/解码/排队中的分配 | P1b |
| GPU 素材池 | P1b 本地原型 ≤64 MiB，surface/UI/驱动另外报告 | P1b |
| 全进程内存/完整包体 | 本地原型 private bytes 预算为播放 ≤550 MiB、同时打开预览 ≤1,100 MiB，解包和 ZIP 各 ≤80 MiB。P4 按正式装配和完整 UI 重新验收 | P1b/P4 |
| 隐藏/稳定性 | 无持续动画提交/无效解码上传；2h 常驻、100 次切换无持续资源增长 | P4 |

记录 CPU/GPU/驱动、OS、DPI、构建 commit/Release 参数、素材哈希、features、进程树。CPU 定义为进程 CPU 时间/墙钟时间（一个逻辑核为 100%）；主进程、解码参照进程和可选集成子进程分列。内存记录 private bytes、working set、峰值、GPU 资源/共享显存，不能只看工作集。

配置素材包时，用 `First asset frame presented` 标记首个素材帧提交呈现，并独立确认拖拽与菜单可用。`First frame presented` 记录窗口首次提交呈现，单列记录。两处素材包都加载失败时不应记录任何呈现。跨页采样覆盖同尺寸纹理复用、末页尺寸变化与循环回首，统计 GPU 同步等待、帧间隔和输入延迟。在自动移动和集成聊天实现后分别纳入对应场景。

启动至少 10 次，报告中位数与范围，区分进程冷启动和系统文件缓存条件；稳定场景预热 2 分钟、采样 10 分钟、至少 3 轮。场景覆盖待机、自动移动、拖拽、切换、聊天和隐藏；记录 CPU、GPU 活跃时间、唤醒、I/O、帧间隔、上传延迟。构建成本分首次下载、干净/增量 Release 时间、峰值内存与工具链体积；完整部署体积包括资源/字体/运行库。

实验分组：

1. 跨实现比较使用相同素材、尺寸、时序和缓存策略，只比较功能已对齐的场景。
2. 同一语言同一渲染路径的全缓存与有界缓存，单独归因；内存不足时记录未完成，双方改用相同子集。
3. 同一 Rust 播放器的参考 FFmpeg、PNG/RGBA、BC7，固定尺寸、帧数、预算，测离线转换成本、画质、包体和运行负载。
4. 最终完整程序重测，不能将模型执行成本算成桌宠开销；无 FFmpeg 运行时目标以干净机包内容和进程调用记录验证。

关键指标回退 >10% 调查；噪声范围内记“未证实提升”。BC7 成为默认需视觉通过、预算通过、至少一项 CPU/唤醒或帧延迟稳定改善，且其他关键指标无未解释回退；若不成立则选择更简单的无损有界路径或重新评估。记录组合方案差异，不将全部收益归因 Rust。

## 4. 发布门槛与回退

P4 必须有需求矩阵结果、窗口/设备记录、所有实际入包动作验证、性能报告、迁移/回退演练、干净机离线验证、版本/哈希/许可清单、已知限制。候选包以实际可分发清单为准，素材删减同步更新交付范围和发布说明。

若外部集成只支持部分客户端版本，发布说明明确版本和能力；不兼容时退出对应功能。回退使用上一可运行检查点、原配置/历史备份和匹配素材包；不要求旧程序读取新 schema。存在未解决数据丢失、越权审批或不可恢复退出问题时不得标为候选就绪。
