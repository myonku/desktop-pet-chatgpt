# 原生重构与工程规范化阶段计划

日期：2026-11-07。状态：规划案，尚未进入功能重写或性能原型实施。

## 1. 决策摘要

2026-11-07 修订：技术栈确定为 **Rust + winit + wgpu/WGSL + Windows API 适配**，辅助设置/聊天界面使用 **egui**。本决定替代先前 C++20/Qt 主线提案，不再建设 C++ 与 Rust 并行候选。

Windows x64 为首发目标，Windows 11 实机优先；Windows 10 的支持范围待锁定依赖版本和驱动验证后决定。Linux/macOS/ARM64 暂缓，不设首版跨平台交付承诺；保留平台接口即可，不提前实现多套后端。

不声称已经证明 Rust/wgpu 比 C++/Qt 更快。winit 负责窗口和事件，wgpu 负责 GPU 绘图；二者不是完整控件库，也不解码视频。这里的原生是本地编译、无浏览器界面的桌面程序，egui 并非 Win32 系统控件。

语言迁移、GPU 渲染、素材格式和缓存策略分别立项与归因。语言切换不以现有全量缓存问题为理由；同时衡量用户侧运行成本和开发侧编译时间、内存、工具链规模。

媒体方向：**以不依赖运行时 FFmpeg 为目标，优先实验离线 BC7 分帧纹理 + 有界 GPU 页池**，PNG/RGBA 分页作正确性基准和兼容候选。FFmpeg 可继续作为离线制作工具及性能参照。是否以 BC7 作为默认资源格式，由原型画质、包体和实际负载决定。

详细原理、候选方案、透明窗口门槛、容量推算和实验设计见 [Rust / wgpu 与无 FFmpeg 运行时评估](G-03-media-rendering-decision-2026-11-07.md)。本轮仍只更新计划，没有开始重写或声称性能验证通过。

## 4. 目标边界与依赖切换

建议结构（仅设计，不在本轮建空目录）：

```text
Cargo.toml + Cargo.lock + rust-toolchain.toml
src/core/                 动作状态机、移动、事件及设置模型
src/ui/                   winit 窗口、egui 界面及气泡
src/render/               wgpu surface、纹理页池、WGSL 管线
src/media/                资源清单、读取/预取和 FrameSource
src/integrations/         共用集成接口、ChatGPT/Codex 与后续 DSH 适配
src/storage/              用户配置、历史、迁移与脱敏日志
src/platform/windows/     Windows 系统服务与局部 unsafe 封装
src/bin/                  离线资源工具入口（必要时独立 crate）
tests/                    单元、契约、GUI 场景与性能测量入口
scripts/                  获取依赖、打包、生成清单、发布验证
docs/decisions/           架构决定及变更理由
```

| 现有依赖/职责          | 目标替换                                          | 切换边界                                                                     |
| ---------------------- | ------------------------------------------------- | ---------------------------------------------------------------------------- |
| Python / PySide6       | Rust / winit / wgpu / egui                        | 用户包无 Python、Qt；桌宠直接绘纹理，控件仅用于辅助窗口                      |
| subprocess / threading | std::process、worker、有界通道                    | UI 线程只接收结果；超时、取消、stderr 持续读取和退出回收                     |
| Pillow                 | 离线图像处理及按需 PNG 解码                       | 不把完整图像工具链带进常驻进程；原 WebP 用途先盘点                           |
| psutil / ctypes        | windows 平台封装                                  | 进程检测、身份和权限错误处理；不直接向核心泄露系统句柄                       |
| sqlite3 / json         | SQLite Rust 适配（优先评估 rusqlite）/ serde_json | 每个读取 worker 独立连接，未知 schema 安全降级                               |
| FFmpeg EXE             | 默认运行资源拟改 BC7 分页                         | FFmpeg 保留离线参考；PNG/RGBA 兼容路径按原型确定                             |
| PyInstaller            | Cargo Release + Windows 打包脚本                  | 固定依赖 features、运行库、完整包内容与许可；不默认宣称单 EXE 无任何外部依赖 |

核心接口建议包括 AnimationCatalog、PlaybackController、FrameSource、Renderer、PlatformServices、IntegrationProvider、HistoryStore。GPU 资源与窗口由事件线程协调，读取/转换 worker 交付有界数据，不跨线程随意操作窗口。资源、用户数据、日志、缓存路径显式分离。

历史迁移先备份、检测格式、写入新位置并校验，保留旧文件；配置加入 schema 版本。回退旧版不能假设它能读取新格式。账号、密钥和历史不进入仓库、日志或发布包。

### 桌面集成边界

桌面版 ChatGPT 是首个目标。现有 Codex 的会话、额度和任务观察路径归入首个适配器。桌面版 DeepSeek Harness（DSH）列为后续集成，在设计阶段预留相同的接入边界，具体协议与支持能力留待实现前验证。

- 桌宠核心消费统一的连接状态、会话与任务事件。适配器负责客户端探测、协议、认证和错误映射。动画、移动和窗口交互可独立运行。
- 适配器按能力声明可用功能，例如任务观察、会话、审批和额度。界面根据能力展示入口，单个适配器离线或故障时仅影响其对应功能。
- 配置、凭据引用、会话标识和任务去重按适配器隔离。现有 Codex 私有数据路径、表结构和协议类型留在首个适配器内部。
- P3 先实现首个适配器，并用合成适配器验证接入、部分能力与故障隔离。DSH 的实际接入和验收单独排期。

## 5. 性能验证设计

先建立可比基线，再作速度承诺。将“编译成原生程序”视为架构目标，将“更快、更省电”视为须测量的结果。

1. **语言对照**：旧 Python 与 Rust 参照路径尽量使用相同素材、参考解码、分辨率、帧数、播放时序和缓存策略；功能不齐时只比较已对齐场景，不拿空壳对完整旧版。全缓存对照若内存不足则记为未完成，并增加双方相同的固定动作子集，不单方面减少素材。
2. **缓存对照**：在同一语言和同一构建下比较全量驻留、按需/有预算缓存与帧队列；单独归因，不混入语言迁移数据。
3. **渲染与格式对照**：在相同 Rust 播放器中分别比较参考 FFmpeg、PNG/RGBA 与 BC7 页资源；由于旧 Qt 与新 wgpu 存在渲染差异，不能把跨产品差值全部称为语言收益。
4. **最终发布场景**：整合方案后重新测完整功能，包含解码器与 Codex 子进程；分别报告桌宠本体、解码进程及可选集成，避免将模型执行成本误判为桌宠开销。

测量条件：记录 CPU/GPU、OS、DPI、素材哈希、构建 Release 参数和进程树。启动区分进程冷启动与资源缓存条件，至少 10 次报告中位数及范围；各稳定场景预热 2 分钟、采样 10 分钟、至少 3 轮。动画帧间隔和输入响应记录 p50/p95/p99，另做 2 小时常驻和 100 次动作切换。DPI 覆盖 100%/125%/150%/200%，包含混合 DPI 多屏。

| 指标           | 记录方式与初始验收建议                                                                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CPU、唤醒、I/O | CPU 按进程 CPU 时间 / 墙钟时间定义为占用一个逻辑核的百分比；覆盖静置、移动、拖拽、聊天、隐藏；隐藏后停掉动画/解码无效工作                                      |
| 帧交付         | 24/30fps 素材按原时序；稳定播放丢帧率暂定 <1%，透明边缘与动作对齐不退化；显示刷新率与素材帧率分别记录                                                          |
| 响应与启动     | 交互响应 p95 暂定 ≤100ms，首次可交互画面暂定 ≤2s；“可交互”要求可拖拽、可打开菜单，不能只显示占位窗口                                                       |
| 内存           | 记录 private bytes、working set、峰值及 GPU 资源；语言对照不预设大幅降幅，另计 GPU 页池、staging 与共享显存；缓存专项另行确定总字节预算                        |
| 长驻稳定       | 切换/隐藏/恢复后句柄、线程、子进程和内存无持续增长趋势；失败可诊断、可恢复                                                                                     |
| 构建负载       | 干净/增量 Release 构建各测时间、峰值内存、下载体积；分别记录首次获取依赖和实际编译；报告 Cargo features、Release 优化与增量条件，不能用 Debug 数据代表用户性能 |
| 部署成本       | 统计可执行文件、素材、字体、运行库等完整产物体积；干净机离线运行，无需 Python/Qt；验证正式媒体路径不调用 FFmpeg                                                |

以上绝对预算是原型初始目标，须在 P0 固定参考机器和测量定义后冻结。等价场景下任何关键指标回退 >10% 必须调查；差异落在测量噪声中就报告“未证实提升”。若收益主要来自工程整理，也应如实报告，不以改语言本身声称性能成功。

## 6. 工程化与发布规范

- **构建可追溯**：固定 Rust/MSVC/SDK 及离线素材工具；Cargo.lock、rust-toolchain.toml、cargo build --locked；记录来源和 SHA-256；控制 crate features 与重复版本。记录源码 commit、工具链、配置、素材/依赖清单及构建日志。可重复构建流程不等于产物已做到字节一致。
- **代码约束**：cargo fmt、clippy、错误类型和模块边界检查；默认安全 Rust，unsafe 限定在平台/FFI 适配并说明不变量；有界消息、清晰所有权和取消生命周期。GPU 句柄封装与设备恢复以行为评审。
- **测试迁移**：复用现有移动、偏好、通知去重、会话复用与异常恢复场景；先做不含 GUI 和未明许可素材的单元/契约测试，再加透明窗口、多屏、托盘、中文输入、睡眠恢复和子进程异常测试。以自有/明确授权的测试图形和合成协议数据运行公共 CI。
- **CI**：Windows 构建、静态检查、无素材测试、打包清单与依赖扫描；第一阶段仅要求 Windows；跨平台逻辑可测试但不增加 Linux GUI 交付要求。GUI offscreen 通过不等于实桌面验收；Windows 实机清单作为候选发布记录。
- **版本与数据**：单一版本源、变更日志、配置 schema 和迁移说明；崩溃/诊断日志脱敏并限量滚动，默认不上传；不向安装目录周期写状态。
- **分发**：优先便携 ZIP，后续再评估安装器/签名。源码包、程序包、素材包分开定义；SBOM、第三方 notices、校验和、支持平台及已知问题随包生成。构建脚本直接复用审定文档，不复制旧的内嵌声明。
- **协作**：新增贡献说明、架构决定、问题模板与维护范围；保留上游归属和修改记录，开发以 fork 为边界，不向 upstream 自动提交。

## 8. 平台范围

首版只承诺实测通过的 Windows x64 环境。Linux/macOS 暂缓，暂不投入 X11/Wayland GUI、托盘或自启适配；逻辑与平台接口分离以保留未来可能性即可。

winit/wgpu 的跨平台性不自动保证桌宠行为跨平台。未来 Linux 项目另立能力矩阵，尤其 Wayland 全局窗口定位与自主移动限制，不能因移除 Qt 就认为协议限制消失。
