# 客户端信息与会话集成

当前 Windows 开发版本可从一个 ChatGPT 来源查询套餐和 Codex 额度。速览汇总和详情切换已用合成的第二客户端复验。DeepSeek Harness（DSH）桌面版的真实适配仍在 M5。首次正式发布的 Windows ChatGPT 对话需要验收显式绑定账号及同一客户端会话。 [现行速览复验](../plan/validation.md#m2-windows-默认连接与自动刷新)

## 产品与接口证据不能混同

ChatGPT、Codex、OpenAI API 是不同接入对象。现有工程没有证明它们共享账户、额度、任务源或会话协议。不能把本开发助手拥有的连接工具当成独立桌宠可调用的 API，也不能把读取 Codex 状态标记为完成 ChatGPT 集成。

DSH 已明确为桌面版，具体仓库、版本、部署方式和用户实际安装实例待核实。实施前由维护者选定实例，或从可确认的桌面安装及官方项目定位，再确定接入方式、权限与数据格式。

首个技术切片应给出下表中的真实证据。只找到客户端进程或版本，可以完成“安装检测”，不能单独验收“基础业务信息查询”。

| 字段候选                        | 首发级别     | 必须验证的语义                                                               |
| ------------------------------- | ------------ | ---------------------------------------------------------------------------- |
| 客户端身份、版本、运行/连接状态 | 基础诊断     | 安装不等于运行；运行不等于认证；实例不能仅靠进程名唯一标识                   |
| 账户/套餐或客户端公开摘要       | 业务字段候选 | 是否可读、是否敏感、属于哪个数据来源；仅在字段语义依赖前台账号时验证桌面绑定 |
| 额度/用量/重置时间              | 业务字段候选 | 单位、分母、窗口、适用模型、时间与时区；不同产品的额度不可互相替代           |
| 当前任务/会话状态摘要           | 业务字段候选 | 是否确有可靠来源、快照还是事件、任务终态的定义；不默认读取正文               |

**首发验收建议**：诊断字段 + 至少一个维护者认可且真实可读的业务字段 + 手动刷新 + 不可用/过期展示。字段清单在接入调查结束时冻结。若没有可靠业务字段，明确记录目标受阻及替代选项，由维护者选择延后集成或改首发范围；不能静默用假数据、进程检测或 Codex 替代。

## 适配器与能力矩阵

优先使用可验证的公开接口或客户端明确支持的本地接口。只读文件/数据库适配仅作为需要维护版本兼容的候选；不预设“只读就是稳定 API”。是否接受未公开接口和版本跟随成本由 D04 决定。UI 自动抓取不作为默认生产架构。

每个字段的接入记录包含：客户端产品/版本/平台、传输方式、来源文档或代码/实际样本、必要权限、原始语义、归一化规则、刷新成本、失败模式、测试版本范围。记录脱敏样本，不保存真实 token 或完整会话。

每个「平台 × 客户端」组合对应一个适配器。同一平台可同时启用该平台的两个适配器。适配器负责定位来源、建立和回收连接、报告能力并转换数据与事件。共用的应用层负责调度、状态和命令路由，窗口与客户端专属页面由所在平台的面板前端呈现。

| 平台    | ChatGPT 桌面客户端                                              | DeepSeek Harness 桌面版                                |
| ------- | --------------------------------------------------------------- | ------------------------------------------------------ |
| Windows | M2 通过独立 App Server 查询所用 ChatGPT 账户的套餐和 Codex 额度 | M5 核实实际安装、版本和接口，验收与 ChatGPT 并行查询   |
| Linux   | 随目标桌面和实际可用客户端版本验证发现、授权及查询路径          | 随目标桌面和实际可用客户端版本验证发现、授权及查询路径 |

M2 使用第二个合成来源验证连接和路由隔离。超时、未知字段和过期由自动测试覆盖。真实平台和客户端的支持范围以各自的接入验收为准。

## 连接设置与来源选择

设置面板独立保存各客户端的连接开关，当前 ChatGPT 桌面客户端默认启用。启用时自动发现和恢复连接；关闭时停止发现，撤销查询并清除该客户端的快照。

发现先按系统会话、包身份和进程代次归并主进程及辅助进程，再按可独立访问的数据来源去重。首期每种客户端最多连接一个来源。自动方式下，只有一个候选时可自动选用；有多个候选时优先沿用仍有效的用户选择，否则由用户在该客户端的连接详情中选择。来源消失时撤销该来源的查询，其他客户端继续使用。对话恢复仍须校验原账号和会话。

当前 Windows 实现以 MSIX 包族和当前系统会话定位客户端，通过桌面主进程及配套 CLI 确认来源。主进程 PID 和创建时间标识本次运行，多个进程或窗口可能共享同一 App Server 登录。桌宠启动的 App Server 使用桌宠进程的本地登录环境。启用后每 15 秒检查客户端。每次刷新前后复核来源，套餐和额度快照在内存中保留并于 5 分钟后过期。

同次刷新在一个 App Server 进程内调用 `account/read` 和 `account/rateLimits/read`。额度采用 `rateLimitsByLimitId.codex`，旧格式仅采用标识为 `codex` 的单桶结果。速览展示各窗口的剩余比例与本地重置时间。套餐和额度查询分别限时 5 秒和 8 秒，额度失败时仍可显示本次套餐。 [App Server 账户协议](https://learn.chatgpt.com/docs/app-server#auth-endpoints)

## 查询契约草案

M2 的 WinUI 命令携带客户端与当前连接代次，worker 回包再携带请求编号和查询所用的实际来源。每个客户端独立维护状态。下列完整字段契约用于后续适配器扩展。

```text
SourceKey = product_id + adapter_id + source_id
Probe -> SourceKey, instance_id, client_version, connection_state, capabilities, unsupported_reason
Capabilities = set of queryable semantic field IDs
Refresh(SourceKey, connection_epoch, request_id, selected_fields) -> Snapshot | Error
Snapshot = SourceKey, connection_epoch, request_id, observed_at, expires_at, fields
Field = key, typed_value, unit?, scope?, source, source_time?, availability
availability = available | unavailable(reason) | unknown | stale
```

桌面安装、运行、来源可用和认证状态分别呈现。连接状态区分 Disabled、Disconnected、Probing、Ready、NeedsAuth、Unsupported、Unavailable。每个字段按实际能力独立降级。时间内部使用 UTC，界面显示用户本地时间或明确时区。缺少来源采样时间时标记本地获取时间。

缓存按数据来源和字段作用域隔离。应用收到结果时核对来源、连接代次和请求标识。进程重启、换来源、认证变化、停用或清除缓存时，撤销受影响的查询并使其迟到结果失效。授权上下文或来源身份发生变化时清除旧快照；同一来源的临时查询失败可保留允许展示的旧值并标记过期。空值、0、无限额、未知和过期分别显示。

每个来源最多一个活动刷新。打开速览后，无近期查询的已连接客户端立即刷新；面板打开期间每 60 秒查询一次。关闭速览后停止定时查询，详情仍支持手动刷新。认证失败和未知版本等待用户处理。退出时仅回收桌宠自己的任务和连接。

## 界面与隐私

速览列出各启用客户端的摘要。每张卡片与该客户端的连接详情共享同一来源的连接状态和查询快照，刷新、清缓存与展开详情均指向该来源。查询期间保留允许展示的旧值并标记刷新中。聊天窗口的客户端切换只改变所显示的页面。 [面板与窗口交互](panels.md#聊天窗口与会话)

自动连接可使用现有授权，缺少授权时显示需认证，由用户主动处理。账户标识默认脱敏，凭据由授权机制管理。日志只记录字段状态、耗时、错误类别与匿名关联 ID。连接详情提供来源和清除缓存入口，停用统一由设置面板管理。

## 对话的后续边界

桌宠通过客户端集成操作用户已授权的真实会话。绑定时明确客户端来源、实例、账号、适用的工作区和客户端会话标识，按此隔离历史、草稿、模型设置、使用量和发送状态。只读套餐授权与对话授权分别处理。发送、停止和流式事件始终按原绑定会话及请求路由。切换客户端或关闭窗口时保留会话视图状态，停止请求由用户显式触发。连接中断后先核对原会话与请求状态，再决定能否恢复。未确认发送由用户决定是否重试。

先在明确授权的 Windows 测试会话中验证同一会话标识和两端消息往返，记录实际支持的客户端版本和会话类型。分别核对普通 Chat、Work 或 Codex 在目标安装中的实际接口范围。公开接口的独立线程可以作为协议实验，正式验收记录须来自客户端可见的同一会话。如果同会话链路或写入权限无法验证，保留 M2 只读体验并记录发布阻塞。

普通 Chat 仍缺少已验证的同会话读取与写入接口，Work 单独验证。Codex 已通过单次同会话发送、文字流、停止和探针重连。直接双写入在实测版本中合并轮次并残留占位，重启客户端后清除了占位。属主队列实验通过双连接同时提交、与桌面发送交错、按原 ID 取消、未提交预留跨客户端重启。两次完成提交确认丢失均在实时观察超时后回查到唯一完成轮次。产品发送接入仍待验证实时收敛、已提交条目在属主退出后的恢复、账号和工作区隔离、升级兼容。 [队列生命周期实测](../plan/validation.md#2026-11-18-队列确认丢失取消与重启)

本机 v13 快照使用 `conversationState.turnHistory.history.entitiesByKey` 保存分页轮次，旧 `turns` 数组可能为空。不能据此判定会话无历史，或在发送确认后把空数组解释为消息丢失。流中可能插入新快照；接收方按 revision 重设基线，并仅在 baseRevision 匹配时应用 Immer 补丁。探针按会话、属主和消息关联 ID 核对实体，只输出验证状态。

本版客户端在 App Server 归一化前直接处理发送文本，要求 `text_elements` 存在。旧探针省略此字段，触发 `text_elements.length` 的 TypeError；历史异常堆栈、安装包原函数复现及修正后双端复验已形成对应证据。明文输入也必须发送 `text_elements: []`。不能仅凭后端轮次完成判断客户端显示正常。

发送确认中的真实轮次 ID 不一定与消息请求一一对应。并发时须分别跟踪请求、用户消息与轮次，不能将同一轮次的任意助手回复用于确认另一条消息。runtime 为 idle 也不代表不存在进行中占位或未确认提交。产品发送前应拒绝这些未收敛状态；本地单写入锁不能仲裁桌面客户端的独立发送，读取空闲快照也没有原子性。

本版属主的 `thread-follower-set-queued-follow-ups-state` v3 是已实测的排队候选。实验使用携带 `preparationMessageId` 的增量预留与完成提交。完整 `state` 替换可能覆盖已有队列。队列确认表明属主接受了条目变更，送达需按原消息 ID 核对轮次和回复，队列清空需核对条目广播和占位收敛。现有通过范围限于上述属主队列样本。

如继续评估私有 IPC，先对打开的本地 Codex 测试会话确认属主和只读快照，再用同一个测试会话验证双端轮次、停止和重连。正式接入前须验证客户端升级后禁用不兼容的方法、Windows 会话与账号或工作区隔离、属主退出和重连后重取快照、切页导致的迟到事件过滤，以及写入超时后通过原会话核对送达状态。共享本地记录读取只适合状态或历史参考。UI 自动化依赖窗口焦点与界面结构，不适合作为后台消息流或写入确认来源。

### 能力与降级

| 能力                 | 实施条件                                                                                                                                                                                                                                  |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 阅读、发送、流式回复 | 以客户端会话为数据来源。按会话和请求关联事件，核对断线恢复、重复事件、未确认发送、中文输入和中止。历史按需读取，桌宠日志只保留脱敏状态。                                                                                                  |
| 对话模式             | 先确认是客户端会话类型还是当前会话中的模式。仅展示当前来源明确支持的模式，验证切换作用域与 UI 状态。Codex 的 `collaborationMode/list` 是实验接口，需要独立版本验证。 [App Server 方法](https://learn.chatgpt.com/docs/app-server)        |
| 模型与推理强度       | 取当前授权来源提供的模型、默认值与推理强度，验证发送后的实际生效值及影响范围。失败时提示原因，沿用客户端有效配置。 [模型目录](https://learn.chatgpt.com/docs/app-server#list-models-modellist)                                             |
| 上下文统计           | 仅使用按会话或轮次归属的真实用量数据与模型窗口上限。累计 token、最近一次请求用量和当前窗口占用分别标明口径，压缩或换模型后按最新来源更新。缺少可比数据时省略占用百分比。 [用量事件](https://learn.chatgpt.com/docs/app-server#turn-events) |

取消、审批和工具输出按客户端能力分别定义。需要客户端处理的交互应显示状态并提供返回客户端的路径。普通桌宠、设置和只读信息可在对话受限时继续使用。
