# 素材协议与制备设计

状态：下一代协议提案。现有工具和读取器仍使用 [v1](../development/runtime-v1.md)，不能直接读取本文拟定字段。本轮不升级 schema、不转换或删除素材。

## 三类资源分开管理

| 类别 | 用途 | 是否随默认安装分发 |
| --- | --- | --- |
| 原始素材 / 画质参照 | 不可变原件、解码参考、裁切/去噪对比、720 全尺寸候选 | 否；原始母版与经 contour 修改的参照必须分开命名 |
| 默认运行包 | 覆盖普通桌宠必需语义、实际显示尺寸的常用质量档 | 是；先确定动作范围与预算，再批量制备 |
| 可选完整 / 高清包 | 全部额外预览动作、更高分辨率或特殊主题 | 独立下载/安装，明确额外磁盘与运行成本 |

全套动作是资源库的完整性目标，不是默认产品必须装入的内容。派生动作按是否有独特视觉价值选择离线生成、共享帧变换或行为回退；不得为了满足十个固定动作名机械地产生十份动画。

## 下一代包的数据模型

| 对象 | 拟定字段 / 约束 | 设计理由 |
| --- | --- | --- |
| 身份 | schema_version、pack_id、pack_version、display_name、作者/来源 | 稳定 ID 与显示名称分离；包版本不再追随应用版本 |
| 兼容 | engine_api、required_features、可选最小 app 版本 | 优先依据能力契约判断；未知必需能力拒绝，未知可选能力降级 |
| 内容 | clips、images、audio、texts；每载荷相对路径、字节数、SHA-256 | 引用去重；体积与解码成本可预检 |
| 语义绑定 | idle、interact、drag、land、move.left/right、dock/peek、可选状态表现 → clip 或显式回退 | 行为由引擎定义，包决定表现；原动作 ID 无需改名才能接入 |
| 几何 | 逻辑画布、锚点、裁切矩形、偏移、播放时序、可选移动时窗 | 分辨率不改变角色占屏大小；裁切不改变锚点 |
| 质量档 | 同一语义内容的候选分辨率/编码、完整性标记 | 安装和解码只选一档，避免把所有 PNG/RGBA/BC7 一起打包 |
| 补充元数据 | 来源台账引用、制备配方哈希、预览图、许可声明 | 来源可追溯；运行不必加载逐帧制备记录 |

建议初版仍为只读目录包；ZIP 仅是运输格式。导入先解到临时目录、校验，再原子发布到用户包目录，运行过程中不原地改写。压缩包导入尚未实现：需要总解压大小、文件数量、单文件、路径穿越、符号链接/重解析点和压缩炸弹限制。哈希是完整性检查，不是作者真实性证明。

### 最小能力与回退

| 绑定 | 要求 | 缺失时 |
| --- | --- | --- |
| idle | 必需，至少一个可循环 clip | 拒绝包，继续使用已确认包 |
| interact / drag / land | 可选 | 当前/基础姿态，不凭空触发移动 |
| move.left / move.right | 对应方向与移动时窗必须合法 | 禁用缺失方向的自动移动；不擅自镜像 |
| dock / peek | 可选，支持共用 clip + 不同变换 | 按平台能力使用基础停靠姿态或关闭特有姿态 |
| 工作/成功/失败表现 | 后续可选 | 使用程序自带状态提示，不反向决定任务真实状态 |
| 名称/海报/音效 | 可选 | 通用名称/无海报/静音 |

素材包可以装饰角色与客户端展示，但不能修改错误语义、权限请求、数据来源或程序身份。建议将应用图标保持为程序身份、角色图标用于角色窗口/托盘主题；是否保留现有应用图标覆盖由 D12 决定。跨平台图标源建议为通用 PNG，ICO 在 Windows 构建/装配时派生。

### 编码与尺寸

PNG 是现有可靠基线，是否继续作为默认编码由对照测量决定。下一代读取器允许某质量档仅有一种已支持编码；GPU 压缩需要能力探测与可安装的兼容档，不在每个包里无条件保留三份同内容。

默认尺寸初选 320 或 384，480 作高 DPI 对照，720 保留画质参照。最终以窗口物理像素（DIP × DPI × 用户比例）、轮廓细节和成本选档，不能只看源文件分辨率。初版建议按安装/启动选固定质量档；动态 LOD 会引入动作对齐、切换抖动和缓存问题，后置。

离线页数按展开字节和纹理最大边长计算，不能为所有尺寸固定同一个 batch。循环动作末页与首尾切换、跨页预取要进入验收。需要紧边裁切时保留一致的逻辑画布与锚点；纯透明 RGB 清零、同帧/同页去重优先于复杂有损编码。

## 制备流水线与停止条件

1. 登记原件来源、哈希和允许用途。原件只读；去噪结果不能覆盖“原始”目录。
2. 写交付内容表：源动作、语义绑定/仅预览/不分发、帧数/时长、分辨率、派生父项、理由。
3. 仅处理待机、粒子/特效互动、30 fps 移动和一组吸边姿态；固定同源帧和时间线比较配方。
4. 在黑/白/彩色背景逐帧及整段检查轮廓、细线、特效误删、闪烁和循环；记录保护区。不以自动图像指标取代视觉判断。
5. 样本通过质量和成本门槛后才装配默认包。全量扩展包单独评估，不阻塞真实客户端查询开发。
6. 校验已声明全部载荷，试播全部实际分发动作，生成文件清单、哈希、来源摘要和安装报告。

每轮只改变一个主要因素。探索最多两组候选后必须形成选择或明确延期，不能无限追加 contour/超分/姿态版本。素材优化工具保留为开发工具，用户运行时不安装 Python、模型或 FFmpeg；若将来采用运行时视频，须单独审定解码依赖、寻帧/切换和平台成本。

## v1 迁移策略

首发可继续发布精简 v1 包，先完成产品路径；只有编码变体、语义绑定或兼容字段确有需要时才引入 v2。提案采用“v1 导入归一化为内部模型 + v2 新包读取”，不原地重写用户包。记录支持的 schema 范围，超前版本明确拒绝。

v1 的未知字段拒绝策略意味着不能在原 manifest 随手添加兼容声明。过渡期可用独立发布清单列出已测试组合，新协议再承接机器可读兼容性。先做两个风格和布局不同的合成包验证契约，避免协议继续由白龙素材的专属处理参数决定。
