## 1. 状态与完成规则

状态使用：未开始、进行中、待验收、完成、阻塞、延期。任务只能在产物可定位且对应验收通过后完成；依赖未满足时不进入下一关口。每次实施更新本表，并在 [G-05](G-05-history.md) 追加日期、提交、验证结果和下一步。阶段 ID 不等于版本号；发版时再决定版本增量。

每个整体阶段使用独立的工作分支，例如 `codex/p1` 和 `codex/p2`。P1a、P1b 在同一个 P1 分支推进。整体阶段验收完成后合入 `main`，下一阶段从合并后的 `main` 建立分支。

P1 后续提交留在本地；合并前将 Windows Rust checks 改为手动触发，再将 P1 提交一次性推送。

## 4. 证据与台账模板

实现时在 `docs/records/` 按模块序列新增记录（例如 `R-01-p0-baseline.md`），当前不建空记录。至少包含：日期、节点 ID、状态、代码 commit、工具链/features、机器/驱动、样本哈希、命令、预期/实际、原始结果位置、限制、决定、下一步。不得填造未测结果。

资源/依赖台账每项字段：条目 ID、类型、来源 URL/提交或本地来源描述、作者/权利主体线索、获取日期、SHA-256、许可证/授权证据位置、允许用途、转换链、拟入包范围、待确认项。账号和私人通信证据只存受控位置，公开文档只留脱敏索引。记录“待确认”不等于已获许可。

节点完成还需：代码和规格一致、有关 F-ID 验收有证据、失败路径已覆盖、无未解释预算超限、迁移可回退、更新 G-05。凡未测项目明确记“未验证”，不得用本轮文档检查结果替代实现验收。
