# 主线实施与验收计划

本文件维护跨阶段依赖、交付范围和验收关口。阶段内的任务状态、决策实验和实测证据见[当前阶段](stages/README.md)与[已验收阶段](archive/README.md)。

## 1. 主线关口

| 阶段 | 前置 | 交付与完成条件 |
| --- | --- | --- |
| P0 工程基线 | 总体设计可实施 | 锁定 Windows 工具链和依赖，建立可重复的构建、合成输入与验证口径，托管构建检查通过 |
| P1a 窗口原型 | P0 | 自有 PNG 透明呈现，alpha 命中、拖拽、托盘恢复、中文输入及混合 DPI 实机验证通过 |
| P1b 媒体原型 | P1a | 离线包契约与多档有界播放通过，实测确定默认格式、分页、降级和预算 |
| P2 普通桌宠 | P1 | 核心行为、平台与设置、存储迁移完成；无网络和外部客户端时仍可使用普通桌宠 |
| P2 与 P3 之间 · 素材工具与发布准备 | P2 | 归档 P2，引入 uv 和素材优化工具初版，以合成输入验收，落实素材来源及发布同版约定 |
| P3 可选集成 | P2 与 P3 之间的工具初版 | 确认可支持的客户端与版本，验收任务与会话、权限、取消、去重及故障隔离 |
| P4 候选发布 | P3 | 全量实机矩阵、2 小时常驻、性能、独立附件、许可清单、干净机离线安装和回退通过 |
| P5 后续扩展 | P4 后独立立项 | DSH、多平台及其他扩展按各自范围立项验收 |

P2 已由维护者验收结项并留存离线可运行检查点。严格断网及无外部客户端的行为复验纳入 P3 基线，有适用环境时执行，最迟纳入 P4 候选。素材试验可以与 P3 并行。 [P2 归档](archive/p2/README.md) · [临时计划](stages/p2-p3/README.md)

### 设备排期

私人和公司两套笔记本都可执行单屏基础回归。设备切换时，先完成当前设备能执行的用例，并在报告中记录设备、GPU、显示模式和 DPI。多显示器专项独立排期，在可用的扩展桌面环境运行，缺设备记为待验收。单屏功能开发、复测和 P3 实施可继续。P4 按最终支持声明核对专项结果，覆盖不足的场景留在已知限制中。实际断网验收继续单独跟踪。[用例、命令与报告规则](G-06-validation.md#多显示器专项)

P3 的第一个节点按客户端和版本记录任务观察、会话、审批、取消、额度各自的接口证据、权限与验证结果。基于已确认能力冻结接口与展示资源契约，再实施任务观察与会话执行，最后验证合成适配器、部分能力、断连和来源隔离。关键能力缺少可验证路径时，记录受影响范围及是否调整候选版交付范围的决定。P4 依次完成全量验收、包与清单、候选版本审定。正式支持范围、安装依赖与发布门槛以 [G-06](G-06-validation.md) 为准。

## 2. 执行与结项

- 维护者确定产品范围、技术方向、用户权限和发布边界。实施者在约定内开发、验证和提交，并在阶段文档中维护任务、依赖和未决事项。跨边界变更先登记设计和影响，由维护者决定。
- 整体阶段从已验收的 `main` 建立独立分支，例如 `codex/p2`。阶段验收后合入 `main`，下一阶段从合并后的基线建立。
- 任务可标为未开始、进行中、待验收、完成、阻塞或延期。完成须满足对应需求和失败路径的验收，报告实测证据、适用范围及未验证项。阻塞时登记原因、已试方案和恢复条件。阶段 ID 与发版版本独立。
- 阶段结项先将仍生效的决定同步到相应常驻文档，再按 [G-05](G-05-contracts.md#文档维护) 归档阶段记录。下一阶段沿用常驻契约，并为当前构建重新采集需要的证据。
