## 版本规则

本仓库从 `v0.1.0` 独立起步，对应源仓库 `v0.5.1` 的迁移重构起点。后续随开发和发布更新版本，由当次改动的范围与兼容影响决定递增层级。修复和兼容性小改动通常增加补丁位，新增能力或阶段性迁移通常增加次版本位。`0.x` 阶段的破坏性变更也应通过次版本和迁移说明明确标记。主版本用于稳定版本的建立或后续重大不兼容变更。

`Cargo.toml` 的包版本作为版本来源。发布时同步更新锁文件、`v` 前缀的 Git 标签和发布说明。

## 文档编号

- 全局文档采用 `G-01-标题.md` 的形式。`G` 代表 Global，`docs/` 及其归档使用同一编号序列。
- 子目录或子模块自管文档采用模块名首字母和两位序号，例如媒体模块的 `M-01-资源格式.md`。编号在模块内分配，同首字母模块通过目录路径区分。
- 新文档取所在序列的下一个编号。修订、改名或归档时保留原编号，同步更新索引与链接。根 `README.md` 保留标准入口文件名，归档中的原始 JSON 清单保留取证文件名。

## 素材管理方向

根目录 `assets/` 留作本地素材工作目录，由 Git 忽略。授权范围明确后，可评估仅追踪带版本和校验值的压缩素材包。需要比较 Git 中的压缩包、单独分发和本地解包三者的成本，尤其关注大型二进制重复提交造成的历史增长。

程序也可以在逻辑上从压缩包读取资源，但应先验证分帧索引、随机读取和预取延迟。整包解压适合作为简单基线，运行时直读有待媒体实验。现阶段保留两种选择。
