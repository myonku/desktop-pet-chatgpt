# 总体设计与推进计划

基线日期为 2026-11-07，补充设计于 2026-11-09 更新。当前包版本为 `0.1.0`，节点状态以 [G-04](G-04-delivery-plan.md) 为准。

## 1. 评估结论

现有方向足以开始原型，但旧计划混合了旧版事实、技术候选、用户需求和交付状态。主要缺口是行为优先级、失败处理、模块所有权、数据契约以及阶段验收证据。本轮补齐这些内容，以 [功能规格](G-02-feature-spec.md)、[架构](G-03-architecture.md)、[任务节点](G-04-delivery-plan.md)、[验证矩阵](G-06-validation.md) 作为实施输入。

保留 Rust 学习与维护价值作为选型依据；性能提升仍需要测量。最先验证透明呈现，再验证媒体管线，最后迁移完整产品，避免在窗口尚不可用时投入全部功能。旧版功能语义和测试场景可复用，旧版全缓存及集中式 Pet 类不照搬。

## 2. 工程事实与范围

P0 工具链与托管 Windows CI 已通过。当前 Rust 原型已实现透明 PNG 首帧、alpha 命中、拖拽、托盘及穿透恢复，素材仍是编入程序的自有 PNG 样本。egui 中文输入与恢复、媒体包加载、完整桌宠行为和客户端连接均待实施。旧工程可从提交 `852f4f4` 追溯，本地忽略目录 `.legacy-v0.5.1/` 用于查阅。实机证据见 [R-02](records/R-02-p1a-first-frame.md) 和 [R-03](records/R-03-p1a-window-input.md)。

首发 Windows x64，Windows 11 优先验收；Windows 10 待依赖与设备验证。单角色、单桌宠实例、本地使用、可离线运行基础桌宠功能。桌面版 ChatGPT 为首个产品集成目标，既有 Codex 会话和任务机制为待验证的技术接入线索，二者不等同于已验证的统一接口。DeepSeek Harness（DSH）后续独立排期。

| 层次 | 本期交付 | 不纳入本期 |
| --- | --- | --- |
| 基础桌宠 | 动作、拖拽、自移动、吸边、缩放、托盘、隐藏、音效、偏好 | 多角色同时运行、素材市场、编辑器 |
| 辅助界面 | 设置、气泡、会话输入、历史与状态 | WebView、复杂富文本执行、插件运行环境 |
| 可选集成 | 能力探测、任务提醒、额度、会话与审批/取消 | 绕过客户端权限、任意私有 schema 兼容承诺 |
| 工程 | 有界资源、迁移、诊断、可追溯 Windows ZIP | 安装器、自动升级、跨设备同步、Linux/macOS/ARM64 |

基础桌宠 P2 可独立验收；包含集成的候选版本须完成 P3。首版不因集成不可用而阻止普通桌宠启动，但不能把缺失的 P3 标为已交付。

## 3. 已定与待证实

已定：Rust stable/MSVC、winit、wgpu/WGSL、Windows 平台封装、egui 辅助 UI；标准线程和有界消息；默认用户包不依赖 Python/Qt，目标不需要运行时 FFmpeg。单 Cargo 包起步，按模块分工，出现独立发布需求后再拆 workspace。

已验证的透明窗口原型采用 P0 锁定的依赖组合和 D3D12/DirectComposition。媒体默认格式、分页封装、兼容媒体路径、资源包分发方式和性能预算待 P1b 实测。BC7 为优先实验，PNG/RGBA 为正确性基准，不能把实验候选写成既定默认。技术原理与既有资料见 [G-07](G-07-media-rendering-decision-2026-11-07.md)，后续实验按锁定版本复核所用 API。

追加设计在 P1b 预留整套素材包替换契约，在 P3 沿用集成适配器契约并拆分客户端专属展示资源。首次启动优先评估基于显示器物理尺寸的默认大小，探测不可行时沿用 256 DIP。具体行为与实现边界见 [G-02](G-02-feature-spec.md) 和 [G-03](G-03-architecture.md)。

维护者负责确定方向、分配任务、维护项目约定，以及决定技术栈、用户权限语义、首版范围和发布边界的变更。实施者（包括受委派的代理）负责在约定内选择实现方案、开发、验证、回填证据和按节点提交。跨边界变更先记录设计和影响，由维护者决定后再实施。

## 5. 风险与处置

| 风险 | 触发条件 | 处置与决策节点 |
| --- | --- | --- |
| 透明窗口不成立 | 黑底、焦点错误或恢复失败 | P1a 停止扩展功能，记录复现；限一个原型迭代调查平台呈现后备，仍不通过则复核后续依赖与范围 |
| BC7 画质或包体不合适 | 边缘可见损伤、无稳定收益或超预算 | P1b 选择 PNG/RGBA 有界路径；不自动回到运行时视频解码 |
| 私有集成变更 | 未知协议/schema、客户端缺失 | 仅禁用对应能力，保留普通桌宠；P3 明确支持版本 |
| 范围膨胀 | 原型被要求同时做素材编辑/多平台 | 放入后续候选，不侵入 P0–P4 |
| 素材与代码许可未明 | 无可追溯分发依据 | 自有测试资源继续开发；相关公开包阻塞，不据此阻塞所有原型 |
| 缺少测试设备 | 第二 GPU/DPI 场景未覆盖 | 记录未验证范围，缩小候选版支持声明 |

## 6. 工程与分发约束

固定工具链、features 和 Cargo.lock；实现提交按节点分拆，附验证证据。Windows CI 从 P0 开始建立构建/格式/静态检查及已有纯逻辑测试，P4 完善打包和清单。GUI 实机验收不能由 offscreen 或编译通过替代。

首期采用便携 ZIP（配置仍写用户数据目录），包含程序、明确来源素材、字体、notices、版本/构建清单、校验值和已知问题。源码包、程序包、素材包分别列清单；构建脚本复用审定文档，不再生成另一套许可文字。压缩素材包是否入 Git 留到 P1b 决定；根 `assets/` 继续忽略，自有小型 fixtures 可随测试代码跟踪。

根 README 保留当前许可声明。上游代码、新增代码、角色/动画、音效、字体、crates、转换器分别登记来源、哈希、许可证据与允许用途；台账模板见 G-04。尚未获得回复的状态不改变授权范围。本轮不添加 LICENSE、不联系第三方、不删除远端发布物或重写历史。

## 7. 设计完成与实现完成分开

设计完成标准包括功能可验收、模块契约可编码、风险有对应实验、任务有依赖与产物、归档链接可达。实现节点按 [G-04](G-04-delivery-plan.md) 的当前队列和验收证据推进。
