# 设计取舍清单

这是维护者的选择入口。**推荐项仍是提案，未回复不等于批准。** 不要求一次决定所有细节；只处理下一切片的阻塞项。每项落定后写日期、选择、理由和替代代价，删除失效候选，避免变成日记。

## 已确认方向

2026-11-14：以当前原型重新规划。Windows 普通桌宠与 ChatGPT 桌面客户端基础信息查询优先，Linux 随后。第二客户端为 DeepSeek Harness 桌面版，对话后置。

2026-11-14：角色右键打开快捷面板，双击查看信息速览，复杂业务进入独立功能中心。托盘负责程序管理与恢复，复杂配置进入独立设置中心。UI 现代化限 Windows 面板，角色沿用现有渲染。Linux 可以独立实现面板前端。框架选型见 D27，交互细节见[面板设计](../design/panels.md)。

## 开始实施前

| ID / 决定点 | 推荐与替代 | 代价 / 何时必须决定 |
| --- | --- | --- |
| D01 首发业务字段 | 真实可读的账户/套餐、额度或任务摘要中至少一种；不能只做安装检测 | 需确认 ChatGPT 版本和字段优先级；M2 编码前冻结。接口无证据时保留不可用，不虚构 |
| D02 Linux 目标 | 先选择维护者实际使用的一种发行版+桌面+X11/Wayland；允许明确降级 | 完整 Wayland 自由定位可能需要专门后端；M3 前风险切片先定环境 |
| D03 DSH 范围与排期 | 核实桌面版的发布来源、版本及接入方式。推荐 Windows 首发后与 Linux 按使用频率排序 | 桌面版已确认，M5 前需核实具体版本和实例 |
| D04 未公开客户端接口 | 优先有文档且可验证路径；未公开只读路径可作为显式实验支持 | 接受就需锁版本、探测、样本和维护成本；不接受而无接口时须调整首发范围 |
| D05 默认内容与下载 | 推荐普通行为语义默认包，完整 39 动作/高清独立可选；默认素材 ZIP 150 MiB、安装 200 MiB 为首轮目标 | 全动作默认会提高带宽/安装/回归成本；720 不默认。批量制备前决定 |
| D06 常驻成本档位 | 推荐先以待机 256 MiB、设置 384 MiB private bytes 作调查目标；实测后冻结 | 与历史约 443/895 MiB 有差距；可接受更高档或更换 UI 策略，但须显式取舍，不无限优化 |
| D07 是否首发上 v2 | 推荐先检查精简 v1 是否够用；仅编码独立分发/语义映射确有收益才升级 | v2 增加读写/迁移/工具成本；继续 v1 则接受 PNG 必需与绑定限制 |

## 素材与交互细节

| ID | 待选内容 | 推荐起点 / 影响 |
| --- | --- | --- |
| D08 质量档 | 320、384、480 默认？高 DPI 下放大质量要求？ | 用实际窗口像素和 E1 视觉选择，720 只作参照；不自动多档常驻 |
| D09 动作范围 | 默认具体动作、额外动作预览、时长/帧率是否可减？ | 保留源时序；先减不常用动作，减少帧率/重做循环必须视觉验收 |
| D10 姿态派生 | 离线独立动画、共享帧变换、允许镜像？ | 保留同侧共享；不默认镜像；品牌/角色允许的形变由素材作者定义 |
| D11 换包体验 | 重启应用还是运行时热换？ZIP 导入还是只选目录？ | 首发“校验后重启”，可先目录导入；压缩包导入增加解压限制与事务 |
| D12 包可定制范围 | 名称、声音、文案、角色/托盘/应用图标、客户端主题？ | 角色可换；权限/错误/来源语义由程序固定；应用身份推荐保持稳定 |
| D13 默认行为 | 声音、自移动、全屏隐藏、预览入口，以及是否提供固定浮层和悬停提示 | 角色双击进入信息速览的默认映射已确定。其他默认值在首发交互验收前选定 |
| D14 初始大小 | EDID 物理尺寸、固定 DIP、启动引导 | 保留 EDID 为可选增强，跨平台用稳定 DIP 回退；是否简化算法待定 |
| D15 无托盘/受限桌面 | 控制窗口、固定停靠模式、禁用隐藏/穿透 | 首选可恢复入口；不允许用户失去控制；决定哪些降级仍算支持 |

## 数据、工程和发布细节

| ID | 待选内容 | 推荐起点 / 影响 |
| --- | --- | --- |
| D16 刷新策略 | 仅手动、面板可见时定时、后台定时？隐藏后是否继续？ | 首发手动；后台默认不短于 60 秒，依接口限额调节 |
| D17 多实例/账号 | 首发只选一个还是同时聚合多个客户端？ | 首发一个选中实例；底层键仍隔离实例，后续不用重做数据模型 |
| D18 数据保留 | 快照缓存寿命、账户脱敏、导出和清除 | 不存正文/凭据，有限快照可清除；对话历史另立设计 |
| D19 兼容承诺 | v1 包保留多久？开发期旧配置/上游迁移维护多久？ | 首发保留当前 v1 读取；开发期允许显式重置但先备份；外部旧版导入可冻结 |
| D20 版本与渠道 | app/pack/schema 解耦？dev/preview/stable？ | 推荐解耦版本，以发布清单锁定组合；预览不是正式兼容承诺 |
| D21 安装形式 | Windows ZIP/安装器；Linux tar/AppImage/发行版包 | Windows ZIP 先；Linux 在目标运行库基线后选择；自动更新后置 |
| D22 默认角色与权利 | 白龙、可分发自有小包、用户自行安装？程序默认图标是否可分发？ | 来源未明确的资产不进入公开包；自有小包可使独立安装不受角色授权阻塞 |
| D23 源码许可与命名 | fork 的许可梳理、产品名是否去特定客户端化 | 保留现有声明直至选定；产品名变化另审数据目录/应用 ID 迁移 |
| D24 CI 与设备 | PR 检查、最低设备、第二笔记本、外屏、Linux 机器 | 合成逻辑自动跑；真实 GUI 按支持矩阵；托管 CI 不假装实机性能 |
| D25 证据保存 | Release 附件/外部存储、保留期、日志脱敏 | Git 留稳定结论和验收入口；日志截图不回灌阶段目录；发布证据需持久可取 |
| D26 对话与提醒 | 对话、任务通知、审批/取消、跨端历史先做哪个？ | 首发后单独按价值排期；不阻塞基础查询 |
| D27 Windows 面板技术 | 优先验证 WinUI 3 / Rust `windows-reactor`。现有 egui 可先承载交互切片 | 根据焦点与窗口调度、长文本、脱机部署和成本结果决定框架及切换时点。Linux 前端随目标桌面单独选型 |

实现中的局部命名、文件拆分、错误文本可由开发者按既定边界自行决定。影响首发价值、支持环境、成本、数据权限或兼容承诺时，才回到本表，不把每个实现细节变成维护者审批。
