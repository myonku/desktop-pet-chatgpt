### M6 普通 Chat 与 Codex 接口实验

2026-11-15，在 Windows 11 22631、ChatGPT MSIX `26.1111.2228.0` 与 CLI `0.169.0-alpha.11.1` 验证。使用用户提供的专用普通 Chat，桌面工具按其 ID 返回该会话记录。将同一 ID 传给配套 Codex App Server 的 `thread/read`，返回协议错误 `-32600`，无法读取该 ID。该实验没有向普通 Chat 发送消息。桌面开发工具的会话权限属于当前开发环境。

使用同一 CLI 启动独立 App Server。通过 ChatGPT 登录发起固定文本的内存 Codex 测试轮次，收到 7 个文字增量和成功完成事件，核对了线程、轮次与回复标记。配套 CLI 的 `app-server daemon version` 也未能连接默认控制 socket（Windows 10050）。没有证据表明该内存会话和桌面已打开的 Chat 属于同一会话，或默认控制 socket 由桌面端提供。

普通 Chat 的同会话读写是发布阻塞。Codex 和 Work 的桌面同会话能力仍需分别实测。脱敏结果在 `artifacts/validation/m6/conversation-probe-2026-11-15/` 的 `ephemeral-final` 与 `desktop-chat-final`。 [复验命令](../development/workflow.md#windows-同会话接口探针)

#### 2026-11-17 属主队列仲裁候选

继续沿用 MSIX `26.1111.2228.0`、流 v13 调查上节直接双写入失败。安装包中存在 `thread-follower-set-queued-follow-ups-state` **v3**，由桌面属主的队列协调器处理。完整 `state` 提交具有替换队列的语义；携带 `preparationMessageId` 时，则在属主存储更新中只合入该 ID 对应的条目。原函数检查确认：新预留保留其他消息，重复预留不重复添加，完成提交保留最初接受时间，缺少预留的完成提交被拒绝。协调器在存在 `preparation` 的队头尚未就绪时不会执行该条目，并按队头和发送锁处理就绪消息。这些是本版安装代码及原函数检查的证据，尚不是升级兼容承诺。

新增 `check-desktop-ipc-queue.ps1`：只允许本轮生成的固定标记、单会话单消息状态、空丢弃列表，以及与消息 ID 相同的 `preparationMessageId`；上下文只携带固定文本、当前会话 cwd 和空附件列表，不覆盖权限或模型。先预留两条，再移除它们的准备标记完成提交；探针不直接调用 `start-turn`。每次变更前保存回执，禁止覆盖旧回执或自动重发。异常退出的清理仅限已确认预留且从未尝试完成提交的本轮条目，不清空整队列。

**单连接候选通过回读与人工界面核对。** 初次执行四次队列变更均获确认，两条消息分别进入不同的完成轮次，但探针对第一条的用户文字报不匹配而提前退出。独立只读检查确认，每条轮次只有一条用户消息及对应标记回复；原生文本制备会在固定请求末尾附加一个 LF。仅对 `DESKTOP_PET_M6_QUEUE_` 测试文字允许这一个末尾 LF，其他文字内容及普通直接发送仍严格核对。修正后按原回执只读核对通过，没有重新提交两条消息；维护者确认两条回复正常且无思考或待发送残留。该只读报告没有实时队列广播，因此其 `queue_presence_verified = false`，不能单独充当协议层队列清空证据。

第二条新专用会话使用两个独立连接分别预留和完成消息，两条独立轮次、回复及队列清空通过。但补充快照显示第二次完成提交前第一条已结束（`active_before_second_completion = false`），故该次只记为双连接顺序执行，不标为真正同时在途。

**两个队列完成请求同时在途的对照通过。** 第三条新专用会话中，两个独立、指向同一已核对属主及桌面进程的连接各预留一条消息，再在读取任何完成确认之前写出两条完成请求，两次写完时间相隔 **2 ms**。探针收到 **10 个队列状态广播**，最终确认两条消息各有一个不同的真实完成轮次、各自一条用户消息、准确标记回复且无工具项。新快照中没有进行中行或未确认提交，队列广播中本次条目数为 0。维护者确认两条回复正常显示，没有持续思考、错误页或待发送条目。共 4 次队列变更（2 次预留、2 次完成），直接 `start-turn` 发送和自动重发均为 0。

该结果提供了与上节直接双写入失败相对照的可用候选：**两次请求同时在途，但由同一个属主队列控制执行**。它没有修复桌面客户端的直接并发 `start-turn` 行为，也未证明任意第三方写入都受同一准入约束。后续优先验证桌面用户发送与队列提交交错、预留或完成确认丢失、取消和属主重启；这些通过后再评估产品发送接入。

证据在 `artifacts/validation/m6/arbitration-2026-11-17/`：`protocol-evidence.json` 为安装包哈希及原函数检查，`owner-queue-pair` 为首次文字校验失败且没有重发的回执，`queue-pair-inspection` 和 `queue-pair-readback` 为归一化及原消息只读复核，`two-queue-writers` 为顺序执行样本，`concurrent-queue-completions` 为真正同时在途的通过样本。IPC 离线检查 **57 项**、原 App Server 探针 **8 项**通过；本轮修改仅限验证脚本和相关文档，既有面板等工作树修改保留。

## 本地实例发现

用 Tool Help 进程快照枚举当前 Windows 会话，仅对可执行名匹配的候选进程核对 MSIX 包族、父子关系与创建时间。在已安装的 `OpenAI.Codex` 版本上，20 次扫描均识别 15 个同包进程、1 个稳定的主进程身份，单轮中位 7.23 ms，最高 10.80 ms。探针只读取本地进程元数据。真实多实例和 PID 复用尚未在这台机器上验收；单实例的退出与重开已由生命周期验收覆盖。 [进程快照](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-createtoolhelp32snapshot) · [包族查询](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getpackagefamilyname) · [进程创建时间](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes)

发现按客户端分别运行。自动方式在启动或应用设置后发现，之后每 15 秒检查；手动方式由用户发起，连接后同样以低频检查来源。已选来源消失时仅撤销相应查询代次，自动与手动方式按各自策略处理重连。业务字段仍由用户刷新。同一客户端有多个独立候选时的选择交互随可验证来源实施。 [连接设置](../design/integrations.md#连接设置与来源选择)

当前实测的桌面启动检测和 App Server 查询需要独立建模。主进程 PID 加创建时间用来识别本次运行，共用同一 App Server 登录的多个窗口或进程只能提供一个可连接来源。同一客户端的发现验收覆盖零、单、多候选、后台子进程归并、取消选择、重启或 PID 复用、来源消失和迟到响应。独立账号或实例的切换先用合成候选验证，真实来源可用时补实测。

## M1 高 DPI 与设置成本验证

2026-11-14 使用 RTX 4060 Laptop / DX12 和 2560×1600、175% 缩放的 Windows 单屏，在隔离配置下测试十动作 v2 默认包。证据位于 `artifacts/validation/m1/display-cost-2026-11-14/`，其中 `source.json` 和 `source.diff` 记录构建输入。

- **交互计时。** 十次热缓存启动到首帧为 368–400 ms。Win32 注入点击到应用呈现日志为 263–266 ms，其中单击与双击区分等待 250 ms。该路径超过 50 ms 的端到端提案，扣除手势等待后的约 13–16 ms 仅是软件链路余量。冷启动与实际显示反馈未测。
- **设置循环。** 274 px 角色窗口待机 440.5 MiB，934×1158 px 设置窗口连续开关 20 次，private bytes 峰值 1,011.9 MiB。末次关闭后为 591.7 MiB，隐藏 5 秒后为 450.8 MiB，恢复后为 452.3 MiB。隐藏期间无动画呈现。句柄从 434 增至 450，恢复后线程回到 19。一轮短测不足以判定残余句柄或长期留存原因。设置功能回归 11 项通过，复测使用前景测试窗口上的实际系统鼠标事件替换了不稳定的定向消息。
- **设置归因。** 隔离诊断构建的分阶段采样显示，面板图形设备和 surface 初始化所在阶段增加约 406 MiB，读取 `msyh.ttc`（微软雅黑）约增加 18.8 MiB。正常字体组首次绘制总增量约 449 MiB，禁用系统字体的对照约 409 MiB。首次字体图集为 8192×64，角色海报纹理为 320×320。初始化阶段的进程增量涵盖设备、驱动与 surface，当前探针未独立拆分这三项。 [性能方案](../design/performance.md)
