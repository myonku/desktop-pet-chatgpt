## 主要偏差与处置

| 优先级 | 发现与证据 | 影响 / 新安排 |
| --- | --- | --- |
| 高 | 旧主线 P3 同时要求任务观察、额度、对话、审批、取消；Linux/DSH 全部置于 P5 | 改为 Windows + ChatGPT 基础信息查询首发；对话后置，Linux/DSH 从现在进入边界设计 |
| 高 | `src/lib.rs` 连 core、storage 都受 `cfg(windows)` 限制；非 Windows 主程序直接返回错误；渲染显式 DX12/DirectComposition | Linux 不是增加编译目标即可；先抽离纯逻辑、路径、窗口和呈现能力，再做真实桌面切片 |
| 高 | 没有 `src/integrations/`；现有菜单和任务气泡配置只是占位；未见真实 ChatGPT/DSH 接口证据 | 首个集成工作项是取得一个真实字段的来源与读通结果；不以 Codex 接入替代 ChatGPT 产品验收 |
| 高 | 旧 80 MiB 原型预算在全量生成后提高到 560 MiB；没有先确定默认交付动作与画质档 | 重新分默认运行包、完整扩展包、源尺寸参照；预算在批量加工前选择 |
| 高 | `Renderer::show` 在事件线程存在每次最多 250 ms 的同步 GPU 等待；Windows alpha region 在事件线程重建 | 有界内存不保证响应流畅；拆分解码、上传、等待、命中成本测量，再决定优化 |
| 中 | `src/ui/mod.rs` 为面板创建自己的 egui context/Painter，读取整份系统 `msyh.ttc`；设置窗口历史峰值接近 900 MiB private bytes | 独立设备、字体、surface 都是调查对象；尚不能认定哪一项是主因 |
| 中 | 正式构建固定 PNG；BC7/RGBA 选择目前由 development feature 提供；v1 每页仍必需 PNG | “改用 BC7 就减小安装包”不成立；需要先设计可独立分发的编码变体 |
| 中 | v1 拒绝未知字段；`pack_version` 未校验为语义版本；旧文档却约定正式素材和程序同版 | 区分现行格式和新提案；版本解耦需要兼容元数据或新 schema，不能只改说明 |
| 中 | CI 仅 `workflow_dispatch`、Windows 单目标；测试通过不能证明 Linux 核心已运行 | 提案增加 PR 自动检查和实际平台测试；编译、GUI、发布支持各自声明 |
| 中 | G 文档混合现状、草案、阶段日记；数据与预算散落多个位置 | 分开用户说明、现行契约、设计、主线与决策；停止新增阶段归档 |

`build.rs` 当前还要求 Windows 主机构建 Windows 图标，不能把 Linux→Windows 交叉编译当成已支持路径。工程初期保留本机原生构建即可。

## 性能证据的边界

核对了本地 `artifacts/validation/p2-p3/full-pack-runtime/result.json` 和 `full-pack-icons-idle/result.json`。对应历史二进制 SHA-256 为 `51ceff108f278375982f9b9e63de6fc12264fd4aafee542e7299da51c77c5e56`，不能代表本轮重新编译的二进制。

历史 320 包：设置打开 private bytes 峰值 895.48 MiB，探头场景 451.26 MiB；设置后隐藏样本仍有 535.41 MiB，8 秒内无帧提交。带图标启动记录为 10 轮、每轮预热 1 秒采样 6 秒。旧待机报告另有 3×24 秒短测。它们支持短时可运行判断，不替代 10 分钟稳定测量、两小时常驻、输入延迟、低配置机器和功耗评估。

用户观察到 720 性能影响；本轮没有重新运行 GUI 性能对照，也未找到与上述 320 完全同条件的 720 完整报告，因此将影响程度和瓶颈归因列为待测。未以通过包校验推断性能达标。

本轮执行 `cargo test --locked --offline --all-features`：28 项单元测试 + 5 项集成测试全部通过。没有把现有自动测试扩展为未执行的实机、严格断网、多显示器或 Linux 验收。
